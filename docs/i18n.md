# Многоязычный сайт: как это устроено и как с этим работать

Сайт собирается GitHub Pages обычным Jekyll-ом (без дополнительных плагинов),
поэтому мультиязычность сделана на соглашениях об именах файлов и на Liquid.
Ничего устанавливать не нужно: добавили файл — появилась страница.

Поддерживаемые языки: **en** (по умолчанию, лежит в корне сайта), **ru**, **zh**.

## 1. Где что лежит

| Что | Где | Кто редактирует |
|---|---|---|
| Список языков | `_data/languages.yml` | один раз, при добавлении языка |
| Подписи интерфейса («Опубликовано:», «Скачать», даты) | `_data/ui-text.yml` | при правке кнопок и подписей |
| Меню в шапке | `_data/navigation.yml` | при добавлении/переименовании пунктов меню |
| Текст страниц | `_pages/*.md` и файлы рядом с `*.ru.md` / `*.zh.md` | постоянно |
| Публикации, доклады, преподавание, блог | `_publications/`, `_talks/`, `_teaching/`, `_posts/` | постоянно |
| Шаблоны (не текст) | `_layouts/`, `_includes/` | редко |

## 2. Правило трёх файлов

Текст живёт в отдельных файлах для каждого языка, рядом друг с другом:

```
_pages/about.md        ← английский (по умолчанию), URL: /
_pages/about.ru.md     ← русский,              URL: /ru/
_pages/about.zh.md     ← китайский,            URL: /zh/
```

То же для записей коллекций:

```
_publications/2019-IOP.md        ← /publication/2019-IOP
_publications/2019-IOP.ru.md     ← /ru/publication/2019-IOP
_publications/2019-IOP.zh.md     ← /zh/publication/2019-IOP
```

Так перевод всегда лежит рядом с оригиналом: проще сравнивать, обновлять и не
забывать про какую-то версию.

## 3. Обязательные поля front matter

Английский файл:

```yaml
---
lang: en
ref: about          # ключ перевода: одинаковый у всех языков этой страницы
---
```

Русский и китайский файлы:

```yaml
---
lang: ru            # или zh
ref: about          # тот же ключ, что у английского файла
permalink: /ru/     # свой URL с префиксом языка
---
```

* `ref` — это «ключ страницы». Переключатель языка ищет по нему файл на другом
  языке. Если перевода нет, кнопка языка ведёт на главную этого языка, а не на
  битую ссылку.
* `permalink` — адрес страницы. Соглашение: английский — `/cv/`, русский —
  `/ru/cv/`, китайский — `/zh/cv/`. Записи коллекций: `/publication/<slug>`,
  `/ru/publication/<slug>` и т. д.
* `lang` у английских файлов можно не писать — он задан по умолчанию в
  `_config.yml`. У переводов писать обязательно.

## 4. Как отредактировать текст

1. Откройте файл нужного языка (`about.ru.md`, `cv.zh.md`, …).
2. Меняйте только текст. Front matter (`--- … ---` сверху) не трогайте, кроме
   полей `title` и `excerpt`, которые тоже переводятся.
3. Проверьте, что неразрывно связанные вещи остались одинаковыми во всех трёх
   файлах: `ref`, `collection`, `date`, `paperurl`, структура `permalink`.

`title` и `excerpt` — это текст, их переводят. `venue` (название конференции),
`paperurl` и ссылки на файлы — обычно оставляют как есть.

## 5. Как добавить новую страницу

1. Создайте `_pages/newpage.md` с `lang: en`, `ref: newpage`, `permalink: /newpage/`.
2. Скопируйте его в `_pages/newpage.ru.md`: `lang: ru`,
   `permalink: /ru/newpage/`, тот же `ref`.
3. То же для `newpage.zh.md` с `permalink: /zh/newpage/`.
4. Если страница должна быть в меню — добавьте пункт в `_data/navigation.yml`
   во все три списка.

## 6. Как добавить язык

1. `_data/languages.yml`: новая запись (`code`, `name`, `short`, `prefix`).
2. `_data/ui-text.yml`: блок с тем же кодом — скопируйте `en` и переведите
   значения. Обязательно переведите `date_format`.
3. `_data/navigation.yml`: список пунктов меню для нового языка.
4. Создайте файлы `<имя>.<код>.md` рядом с английскими с тем же `ref`.
5. Готово: переключатель сам покажет новый язык, меню и подписи подхватятся.

## 7. Подписи интерфейса

`_data/ui-text.yml` — единственное место для служебных слов: «Опубликовано:»,
«Скачать», «Читать далее», подписи форм комментариев, формат даты.
Шаблоны берут их как `site.data.ui-text[page.lang].<ключ>`, поэтому **любой
новый ключ нужно добавлять во все языковые блоки**, иначе в этом языке
останется английский вариант из `| default:`.

Формат даты задаётся там же ключом `date_format`
(`%B %d, %Y` для английского, `%d.%m.%Y` для русского, `%Y-%m-%d` для китайского).

## 8. Как это работает внутри (для правки шаблонов)

* `_layouts/default.html` ставит `<html lang="{{ page.lang }}">`.
* `_includes/language-switcher.html` — сам переключатель. Он ищет в `site.pages`
  и `site.documents` файл с тем же `ref` и нужным `lang`.
* `_includes/masthead.html` берёт меню из `_data/navigation.yml` по языку
  страницы.
* Списки (`publications.md`, `talks.md`, `teaching.md`, `year-archive.md`, `cv.md`)
  фильтруют коллекции по языку страницы:
  `{% assign posts = site.publications | where: "lang", page.lang %}`.
* Стили переключателя — `_sass/custom.scss`, подключается в
  `assets/css/main.scss`.

## 9. Ограничения и подводные камни

* **Плагины недоступны**: GitHub Pages собирает сайт в безопасном режиме,
  поэтому нельзя использовать jekyll-polyglot и подобное. Всё сделано на
  Liquid и соглашениях об именах.
* **Даты**: `%B` в Liquid всегда даёт английские названия месяцев, поэтому для
  русского и китайского используется числовой формат.
* **Страница 404** одна на весь сайт (`/404.html`), язык у неё не переключается.
* **Служебные страницы** шаблона (`terms.md`, `markdown.md`,
  `archive-layout-with-content.md`, `sitemap.md`, `portfolio.html`) не переведены:
  это демонстрационные страницы темы, они не входят в меню.
* **Индексирование**: у каждой страницы свой `lang` в `<html>` и свой
  `og:locale`; при желании можно добавить `hreflang`-ссылки между переводами.
